# Desktop UX audit — 2026-10-22

Jarvis should match the completeness of everyday flows: start, compose, supply context, follow progress, recover, find work, and resume. Adding controls without working behavior makes the product less trustworthy.

## Evidence and limits

- Researched current official OpenAI and Anthropic documentation. Checked local files first; this repository contains integrations, not official ChatGPT product documentation. OpenAI sources below use ChatGPT Learn.
- This is a documented-flow audit, not an authenticated walkthrough of either installed application. Exact toolbar placement, animation timing, and undisclosed experiments remain unverified. Jarvis screenshots and interaction tests must establish the implementation's visual quality separately.
- Product names and availability are moving. Current OpenAI documentation describes Chat, Work, and Codex in the desktop app. Claude's Chat/Cowork unification and new project experience are staged rollouts. These are not universal layouts to copy. [ChatGPT desktop](https://learn.chatgpt.com/docs/app), [Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork), [Claude projects](https://support.claude.com/en/articles/9517075-what-are-projects).
- Product capabilities do not establish capabilities of Jarvis's subscription adapters. Preserve Jarvis's own conversation storage, cross-provider identity, and memory scope. Do not imply native provider history or project synchronization.

## Baseline Jarvis findings

Observed in source before this polish pass; this is an audit snapshot, not a claim about the final implementation.

| Area | Already present | Gap or risk |
| --- | --- | --- |
| Composer | Growing textarea, file chips, drop/paste, Send/Stop, model picker, conditional browser dictation. | Draft is component-local; no durable per-chat draft. No hint for Enter/Shift+Enter. Attachment read/acceptance state is not represented. |
| Attachments | Name/size/type metadata; previews for images at most 512 KB; 10-file/20 MB validation. | `providerClient.ts` serializes history as `{ role, content }`, dropping attachments. Accepted chips therefore do not establish delivery. Non-preview files retain no bytes. Fix transport or clearly restrict unsupported input. |
| Messages | Markdown, copy, edit, regenerate, feedback, read-aloud, model labels, tool activity. | Actions rely heavily on hover. Failures use message content, and an empty stopped assistant message can resemble ongoing generation. Tool-only responses need a clean completed state. |
| History/search | Pin/archive, title/content matching, snippets, keyboard cursor, project grouping. | Search lacks a robust focus lifecycle. Result count/empty/recent modes and visual match emphasis can improve. Archived results are excluded, so recovery needs an obvious separate route. |
| Projects | Instructions, recent chats, move existing chats, delete project without deleting chats. | Instructions/chat list have weak hierarchy. No persistent project file library. Avoid implying knowledge uploads already exist. |
| Settings | General, personalization, subscriptions, tools, data controls; dark/light/system. | No send-shortcut preference. Modal has initial focus and Escape but no focus trap/return. Subscription count treats a recorded plan as linked, while status may say disconnected. |
| Chat surface | Empty screen, streaming skeleton, prompt anchoring, Jump to bottom, split-panel support. | Empty and active composer layouts must stay consistent. Documented product polish depends on clear waiting/recovery states, not adding more panels. |

## Implementation priorities

These are design recommendations inferred from the evidence and Jarvis source, not claims that every competitor implements them identically.

1. **Complete the composer lifecycle.** Use a two-row composer with stable controls; durable draft per conversation/new-chat/project; clear send key; accessible labels; remove/clear attachments; guard against sending while context is still processing. Suggestions should prefill rather than submit unexpectedly.
2. **Make capability and failure states truthful.** Adapter readiness should be visible before send. Keep attachment affordances consistent with actual file delivery. Missing providers should open the relevant setup path. Retry must preserve the prompt; Stop must leave a settled transcript. Do not silently substitute a model.
3. **Make navigation effortless.** Distinguish primary navigation, projects, pinned work, and recents. Improve history density and selected-state contrast. Add result counts/snippets, visible search shortcuts, keyboard operation, archive access, and clear no-result guidance.
4. **Use consistent interaction primitives.** Focus-trapped dialogs with return focus; keyboard-operable menus; Escape behavior; named icon buttons; hover/focus/pressed states; reduced-motion support. Destructive actions must identify the affected item and outcome.
5. **Polish reading and progress.** Comfortable line measure, coherent message spacing, restrained model metadata, grouped tool details, explicit pending/stopped/error states, readable code/tables, and message actions visible on focus/touch.
6. **Give projects and settings substance.** Project overview, instruction editor with save/cancel feedback, recent work with dates, clear context scope. Settings should distinguish app preferences, provider connection, and local-data actions, with a keyboard reference and send behavior.

## Beyond this UI pass

Capability work should have explicit end-to-end acceptance criteria before its controls appear as available: provider-native image/file transport; project source ingestion; native dictation/voice; OS screenshot/window capture; global quick entry; completion notifications; cloud task continuity; actual mid-run steering/queueing; provider history import/sync; full artifact editors; shared/team projects. An SDK or subscription adapter does not grant native product parity for any of these.

## Acceptance walkthrough

- New chat → type multiline draft → change chat/project → return/reload → draft restored in the correct scope.
- Choose connected model → send → see pending/streaming → Stop → partial response remains and all activity settles.
- Choose unavailable model or lose connection → meaningful recovery action → retry without duplicate user messages or lost prompt.
- Add supported context by picker/drop/paste → inspect/remove → send → verify actual adapter payload. Reject unsupported formats clearly.
- Edit an earlier prompt → understand effect on later turns → cancel safely or send → copy response with confirmation.
- Search title and message phrase → navigate results with keyboard → open selected chat → return focus correctly after dismissal.
- Pin/rename/archive → recover archive → verify title, project, and message data survive reload.
- Project instructions → edit/save/cancel → send within project → verify instructions reach the provider.
- Open every dialog/menu with keyboard → operate it → Escape → focus returns to the trigger; background controls remain unreachable while modal.
- Inspect localhost screenshots at desktop and narrow widths in both themes; run two visual comparison rounds, then verify critical flows interactively.

Unresolved evidence: exact current competitor message-toolbar inventory and account-specific rollout layouts; native UI walkthrough required to claim pixel-level parity.
